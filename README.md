# KidsLab

**Robotics, Coding, Creativity**

KidsLab is a children's learning club focused on helping children learn through **building, coding, experimenting and creating**.

I created KidsLab because I believe children should not only learn technology by sitting in front of a screen. They should be able to build things, make mistakes, solve problems, experiment with ideas and see their ideas come to life.

The club combines three main areas:

* **Robotics**: Build and program robots and physical projects
* **Coding**: Learn programming through fun, practical projects
* **Creativity**: Turn ideas into games, inventions and creative technology projects

## About the Project

This repository contains the website for KidsLab.

The website is designed to give parents a simple and clear overview of:

* What KidsLab is
* What children learn
* The different activities and projects
* How the learning experience works
* Upcoming sessions
* How parents can register or get in touch

The goal is to keep the website modern, simple, playful and trustworthy.

## Our Mission

My goal with KidsLab is to create a space where children can explore technology in a different way.

Instead of only learning theory, children will:

**Build → Code → Experiment → Solve → Create**

I want children to leave each session feeling like:

> "I made this."

## Getting Started

To run the project locally:

### 1. Clone the repository

```bash
git clone https://github.com/YOUR-USERNAME/kidslab.git
```

### 2. Open the project

```bash
cd kidslab
```

### 3. Install dependencies

```bash
npm install
```

### 4. Start the development server

```bash
npm run dev
```

The website should then be available at:

```text
http://localhost:3000
```

## Environment Variables

Private credentials and API keys should never be committed to GitHub.

For local development, create:

```text
.env.local
```

Example:

```text
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
```

The `.env.local` file should remain in `.gitignore`.

When the website is deployed, environment variables should be added through the hosting platform instead of being placed directly in the source code.
